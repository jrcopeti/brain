# A plan for each piece of work, with a devlog beside it

**Rule:** each piece of work gets its own tracked folder, `docs/<topic>/`, holding a `PLAN.md` and a
`DEVLOG.md`. Both are required. There is no repo-wide devlog. Read the plan at the start of a task
and keep both files current.

**Why:** the next agent or person picks up from these files, not from memory. The plan looks ahead
(the steps, where the work stands, what comes next). The devlog looks back (what each branch
built, what each review found, what was measured). Status lives in one place, so it doesn't drift.

**How:** new work gets a new folder with both files. Add devlog entries at the end, and keep an
index of each finished branch's state. Anything a branch leaves open that is worth doing goes in
both files. Nothing else repeats status. A lasting decision goes beside what it governs.
