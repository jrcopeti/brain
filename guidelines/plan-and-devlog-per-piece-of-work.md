# A plan and a devlog for each piece of work

**Rule:** each piece of work gets its own tracked `docs/<topic>/PLAN.md`. Read it at the start of
a task and keep it current. A devlog records what the plan's branches built, each review's
findings, and what was measured, with new entries last.

**Why:** the next agent or person picks up from the plan, not from memory. The status lives in one
place, so it doesn't drift.

**How:** new work gets a new folder. The plan says what comes next. Anything a branch leaves open
that is worth doing goes in both the plan and the devlog. Nothing else repeats status. A lasting
decision goes beside what it governs.
